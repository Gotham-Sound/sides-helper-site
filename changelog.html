Sides Helper Changelog

One entry per build that reached testers, newest first. The build number is in Settings on both platforms and in the Mac disk image's Read me first. The same page is on the site at https://gotham-sound.github.io/sides-helper-site/changelog.html.

Build 125, 2026-09-22

  • The Mac disk image is signed with a Developer ID and notarized by Apple, the first one that is: it opens like any app, with no Open Anyway step, and its Read me first no longer has that section. The 122 image was the last unsigned one.
  • Open PDF with sides already open starts a new packet with the file you pick; the old packet's roster, KEY and notes are remembered the way Close packet remembers them. Add another PDF still adds to the open packet. Before, Open PDF with a packet open added the file to it, or, for the same file, replaced it in place, which looked like nothing happened.

Build 122, 2026-09-22

  • The Mac disk image of this build is unsigned like the ones before it (the Open Anyway step in the Read me first); the signed, notarized one follows when Apple finishes its first look at the app, a day or two for a new developer account.
  • The scene lock is off unless you turn it on: the bar's lock capsule or Display > Follow > Stay in the scene. Once on, it stays on. Build 120 had it on by default; the tester who asked for the lock wanted it the other way, and he is right that the first day with the app should behave as before.

Build 120, 2026-09-22

  • Follow stays in the scene. With the lock on, which is the default, the page cannot be moved to another scene by what the room says; when the room sounds like another scene, a chip in the rail offers it and one tap moves there. A tap on a line, Top of scene or the scene list move the lock with you. The lock capsule in the bar shows the scene number; tap it to follow across scenes, as for a shot that runs from one scene into the next. Display > Follow > Stay in the scene is the same switch.

Build 119, 2026-09-22 (iPad)

  • Pinch the page to size it. Two fingers set the text size of the layout you are in, Screenplay or Reader, live as you pinch, and Display shows the same value. It sticks. With Follow on, the page comes back to the current line when you let go. On the Mac the trackpad pinch does the same.

Build 115, 2026-09-22 (Mac)

  • After Close packet, an Open PDF that fails (a file still in iCloud, a slow disk) now shows its message instead of looking like nothing: the open waits for the panel to close first. The diagnostic report records the Open panel's answer.

Build 113, 2026-09-22

  • Sixteen highlight colors instead of eight: coral, rose, orchid, periwinkle, aqua, lime, gold and tan join the first eight, in the KEY, on the page and in the export PDF, and in the free web tool. The four highlighter colors still come first. There is no gray on purpose: a gray highlight looks like the shading sides use for omitted text.

Build 110, 2026-09-22

  • Follow always turns off. Before, a tap on Follow was ignored while the speech model was still loading after a turn-on, which on an iPad's first run is a minute; the button now says "loading the speech model" during that time and a tap turns Follow off at any moment.
  • On the Mac, Open PDF, Add another PDF and Cmd-O use the Mac's own Open panel. Before, after Close packet, Open PDF could show no window at all.
  • A tester log: every report, user error included, is written down with what it pointed to and what changed.

Build 107, 2026-09-22

  • Settings has a User manual link that opens the manual in the browser. The manual itself is at https://gotham-sound.github.io/sides-helper-site/manual.html, current for both platforms with fresh screens.

Build 104, 2026-09-22

  • The Follow unlock reads $49.99 everywhere, matching the price on the App Store sheet.
  • The build number shows in Settings, About and the diagnostic report; the Mac read-me says it too.
  • A PDF opened again replaces its copy in the packet instead of being added twice. Notes re-attach and the cursor stays.
  • A slow line is given its own time: once enough of a line has been heard, that line's own pace sets how long the rest is expected to take when it says the line runs slower than average, so the next name lights later on a slow line rather than early.

Build 100, 2026-09-21

  • The audio input on the Mac is captured through an audio unit pinned to the device you pick. Before, picking any device whose sample rate differed from the Mac's default input captured nothing, silently, and a stereo device beside a mono default gave channel 1 only. Devices are remembered by a stable identifier, so a pick survives re-plugging and a reboot.
  • Only an input you picked in Feed + STT check is remembered. With nothing picked, a recorder over USB is used when one is plugged in, otherwise the built-in mic, and that guess is never written down as your choice. A pick that is unplugged when Follow turns on is named in an alert; another feed stands in if one is there, the built-in mic never does.
  • Sum in the channel picker is channels 1 and 2 only. Before, it averaged every channel the device offered.
  • The text under the macOS microphone prompt says the input you pick, USB feed included, is what is used.

Build 97, 2026-09-21

  • The first open after the app had sat idle for a few seconds no longer hangs on the Mac: the sides engine's web view lives in the window, where macOS does not suspend it.
  • An open that stalls says so with a message after a set time instead of spinning forever, and the diagnostic report carries the engine's own log.
  • Settings, and with it Send a report, are reachable before any sides are open: on the first screen, and on the Mac under the app menu.

Build 91, 2026-09-21

  • The first TestFlight build. The sides tool, the KEY, Follow with the Page, Drum, Horizon and Picture displays, notes and flags, Print / Export, the sample sides, Open a sides link, Send a report.
